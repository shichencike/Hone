#0. 快速入门：从零到第一个脚本

新手请先走完本节（约 5 分钟）：安装 → 写第一个脚本 → 运行 → 基础语法，跑通最小闭环后再逐章深入。

第 1 步：安装（任选一种，详见安装教程）

// Linux / Termux
curl -fsSL https://github.com/shichencike/Hone/releases/latest/download/install.sh | sh
// Windows（PowerShell 5.1+）
irm https://github.com/shichencike/Hone/releases/latest/download/install.ps1 | iex

验证：hone --version

第 2 步：写第一个脚本

新建 hello.hn，内容只有一行：

print("Hello, Hone!");

第 3 步：运行

hone hello.hn     // 输出 Hello, Hone!（hone run hello.hn 等价）

Hone 是解释型脚本语言：无需编译、无需 main 函数，顶层语句从上到下顺序执行。

第 4 步：基础语法速览

// 变量：无前缀声明，类型推导后锁定

f = 3.14;            // float
s = "hello";         // str
b = true;            // bool

// 控制流：条件必须是 bool
if (x > 5) { print("大"); } else { print("小"); }

// 函数：返回类型由 return 推导
fn add(a, b) { return a + b; }

// 集合与遍历
nums = [1, 2, 3];
for v in nums { print(v); }

#3. 数据类型与变量

静态强类型：类型一经推导或显式声明即锁定，禁止隐式转换。

x = 10;              // 自动推导为 int
f = 3.14;            // 自动推导为 float
y : int = 20;    // 显式类型（Rust/TS 风格）
int z = 30;      // 显式类型（C 风格）
x = "Hone";          // error[H001]: 期望 int，得到 str
类型说明字面量示例
int64 位有符号整数0, 42, -1
float64 位双精度（IEEE 754）3.14, .2, 2.0
bool布尔值true, false
strUTF-8 字符串"hello"（支持 \n \t \\ \"）
ptrFFI 不透明指针句柄（void*，用于 load 动态库调用）load 返回值 / 0 表示 NULL
list动态列表（元素类型不锁定）[1, "a", true]
dict动态字典（字符串键 → 任意值）{"name": "hone", "ver": 1}

#5. 控制流

条件表达式必须显式返回 bool，禁止隐式转换（if (1) 视为非法）。

if (x > 5) {
    print("大");
} else if (x > 0) {
    print("小");
} else {
    print("非正");
}

i = 0;
while (i < 10) {
    i = i + 1;
}

// for-in：遍历列表（单变量）或字典（键、值双变量）
nums = [1, 2, 3];
for x in nums {
    print(x * x);      // 1 4 9
}

user = {"name": "hone", "ver": 1};
for k, v in user {
    print(k + "= " + to_str(v));
}

#6. 函数

fn add(a : int, b : int) -> int {
    return a + b;
}

// 参数类型可由调用上下文推导（推荐复杂场景显式声明）
fn greet(name) {
    print("你好, " + name);
}
  • 函数返回类型由 return 推导，也可用 fn f() -> type 声明
  • 无返回值时调用作为表达式得到 null 占位
  • 所有函数扁平化存在于全局符号表（不支持 :: 路径）

泛型函数

在函数名后、参数列表前用 [T, U] 声明类型参数，参数与返回类型注解可引用 （x: T、-> T）。调用时按实参自动推导，同一泛型函数 可以不同类型多次调用、互不锁定；编译期擦除——运行期与普通函数零差异，无运行时开销、不产生重复代码。

fn identity[T](x: T) -> T {
    return x;
}
print(identity(42));          // 42（T=int）
print(identity("hello"));     // hello（T=str）

fn swap[A, B](a: A, b: B) -> B {
    return b;
}
print(swap(1, "two"));        // two（A=int, B=str）

fn pick[T](a: T, b: T, want_first: bool) -> T {
    if (want_first) {
        return a;
    }
    return b;
}
print(pick("a", "b", true)); // a（T=str）
print(pick(10, 20, false));  // 20（T=int）

约束：函数名全局唯一（泛型与普通同名仍报 already defined）；未声明的类型参数报 H002； 重复类型参数报 H005；同一类型参数处调用点必须传同型（否则 H001）。 类方法同样支持泛型（class 中 fn 方法[T](...)）。 完整示例见 examples/generic_test.hn。

#7. 集合与字符串

列表 [a, b, c] 与字典 {"k": v} 为动态集合类型：元素类型不锁定、可混合， 变量本身仍遵循类型锁定规则（不能把列表赋给已锁定的标量变量）。

nums = [1, "a", true];          // 混合元素列表
user = {"name": "hone", "ver": 1};   // 字符串键 → 任意值

print(len(nums));               // 3（元素个数）
print(to_str(user));            // {name: hone, ver: 1}

l = append(nums, "x");          // [1, a, true, x]（返回新列表）
print(contains(l, "a"));       // true
print(index_of(l, "x"));       // 3（找不到返回 -1）

print(has_key(user, "name"));  // true
print(to_str(keys(user)));      // [name, ver]
print(to_str(values(user)));    // [hone, 1]

f-string 字符串插值：f"..." 内 {expr} 嵌入任意表达式， {{ / }} 转义字面大括号：

name = "hone";
print(f"你好, {name}! sum = {1 + 2}");   // 你好, hone! sum = 3
print(f"{{{1 + 1}}}");                 // 字面大括号 + 表达式

类型判断：is_int is_float is_str is_bool is_list is_dict is_null，判断运行期值类型，常用于分支处理混合集合。

#7.5 结构体 · 模式匹配 · 管道

struct 结构体：声明确定的数据形态（字段名与类型固定），实例用 dict 表示、字段访问 p.字段； 构造时按字段顺序传参，检查阶段校验字段个数与类型（H001/H011）：

struct Point { x: int, y: float };
p = Point(3, 2.5);
print(p.x);   // 3
print(p.y);   // 2.5

match 模式匹配：多分支表达式的简洁写法，模式支持字面量与 _ 通配符（放最后、只能一次）， 返回匹配分支的值，全部不匹配时运行时报错（建议补 _ 兜底）：

s = match 2 {
    1 => "one",
    2 => "two",
    _ => "other",
};
print(s);   // two

管道操作符 |>：数据流向更直观。x |> f 等价 f(x)， x |> f(a, b) 等价 f(x, a, b)，可链式（解析期转换为普通调用）：

print("hello world" |> len);       // 11
print([1, 2, 3] |> len |> to_str); // "3"

#7.6 class 类（成员函数不进全局符号表）

class 类：将一组相关函数组织成命名空间，通过 类名.方法(...) 调用 （如 Math.double(21)）。关键特性：成员函数不进入全局符号表—— 不能用裸名调用（double(21) 报 H002），不污染全局命名空间， 同名全局函数可与类方法共存、互不影响；类内方法互相调用也要用限定名 （return Math.fib(n - 1) + Math.fib(n - 2);）。

class Math {
    fn double(x) {
        return x * 2;
    }
    fn fib(n) {
        if (n <= 1) {
            return n;
        }
        return Math.fib(n - 1) + Math.fib(n - 2);
    }
    fn greet(name) -> str {
        return "Hello, " + name;
    }
}

print(Math.double(21));   // 42
print(Math.fib(10));      // 55
print(Math.greet("hone")); // Hello, hone

fn double(x) {            // 全局同名函数与类方法共存
    return "global: " + to_str(x);
}
print(double(21));        // global: 21
print(Math.double(21));   // 42（类方法不受影响）

类方法支持参数、返回值（可写 -> type 注解）、递归、return，与普通函数能力一致； 类名与 struct 名不能重复（报 H005）；结尾分号可选（class 是块结构，与 struct 不同）。 完整示例见 examples/class_test.hn。

#9. 导入与外部集成

// import：远程模块下载并缓存到 ~/.hone/cache/（URL 支持 http/https）
import "math_mod" from "http://example.com/math_mod.hn";
 print(module_add(20, 22));

 // import as：以别名导入，函数名前缀自动替换
 import "math_mod" from "http://example.com/math_mod.hn" as m;
 print(m_add(20, 22));

 // load：动态库加载（C ABI，int64 参数/返回值）
 load "path/to/hone_lib.dll" as m;
 print(m.lib_add(1, 2));

 // typed FFI 签名块（v0.4+）：显式声明参数/返回类型，精确转换
 load "path/to/hone_lib.dll" as tm {
     fn lib_add_f(a: float, b: float) -> float;
     fn lib_strlen(s: str) -> int;
     fn lib_not(b: bool) -> bool;
     fn lib_echo_ptr(p: ptr) -> ptr;
     fn lib_bump() -> void;
 }
 print(tm.lib_add_f(1.5, 2.25));  // 3.75（float 通道）

 // from 头文件自动绑定（v0.4+）：从 C 头文件提取原型生成签名
 load "path/to/hone_lib.dll" as hm from "path/to/hone_lib.h";
 print(hm.lib_strlen("hello"));  // 5

 // hone bind：离线从头文件生成签名块，粘贴进脚本即可
 // hone bind path/to/hone_lib.h  →  输出 load 签名块到 stdout

typed FFI（v0.4+）：签名块内 fn 声明仅描述 C 函数 ABI，不定义 Hone 函数体。 支持类型映射：int → int64_t、float → double、bool → C bool、 str → const char*、ptr → void*；返回类型额外支持 void； 参数最多 8 个，回调 fn(...) 与可变参数 ... 暂不支持。 调用在检查阶段校验参数个数与类型（H001/H005），返回类型参与类型推导。 未声明签名的库函数保持旧 int64 通道调用（向后兼容）。

头文件自动绑定（v0.4+）：load ... from "header.h" 用受限解析器 （纯 Rust，无 libclang 依赖）从 C 头文件提取函数原型自动生成签名：跳过注释/预处理/struct 定义/extern "C" 块， typedef 简单展开，属性宏跳过；类型映射 int/size_t→int、float/double→float、bool→bool、char*→str、 其余指针→ptr、void→void。回调/变参/数组/结构体按值/long double 标记 unsupported，调用时直接报错而非 ABI 崩溃。 hone bind <header.h> 离线生成签名块输出到 stdout，unsupported 原型列为注释。

示例：examples/ffi_demo.hn（typed FFI 全类型）、examples/ffi_header.hn（头文件绑定）。

#11. 错误处理

错误统一为 error[Hxxx] 格式：编译期静态检查报错，运行期可恢复错误用 try-catch 捕获。

error[H001]: type mismatch: variable `x` is locked to `int`, got `str`
  --> err.hn:3:1
3 | x = "Hone";
  | ^
help: Hone types are locked after inference; no implicit conversion is allowed
错误码含义
H001 ~ H012类型 / 语法 / 推导 / 运行期基础错误（含泛型同一类型参数处实参不一致、类方法裸名调用、类型参数重复声明等，见下）
H101 ~ H104词法语法细分：非法字符 / 未闭合字符串 / 未闭合注释 / 缺少分号
H200 ~ H204网络：请求失败 / 超时 / 连接拒绝 / DNS 失败 / 非 2xx 响应（http_get / http_post / http.request / smtp.send / ws.request）
H300 ~ H303系统 / DLL：系统调用 / 库加载失败（含 sqlite 库缺失）/ 参数校验 / 权限不足
H304 ~ H305指针：野指针（未分配/已释放/重复释放/空指针）/ 越界访问（ptr 类）
H401 ~ H404文件：不存在 / 权限不足 / 被占用锁定 / 通用 NOT_FOUND
H600throw 主动抛出的用户错误
H700assert 断言失败（测试框架）
H999尚未实现

class / 泛型 / 新模块相关报错：

  • H001 泛型：同一类型参数处实参类型不一致（如 pick[T](a: T, b: T) 两次实参需同型）
  • H002 类方法裸名调用（成员函数不进全局符号表，必须 类.方法(...)）；泛型注解引用未声明的类型参数
  • H005 类型参数重复声明（fn dup[T, T]）、类名与 struct 名重复、类成员非 fn 定义
  • H011 struct 构造 / 类方法调用的参数个数不符
  • H301 sqlite 库缺失：Linux 安装 libsqlite3，Windows 将 sqlite3.dll 放到 hone.exe 旁边

完整解释与修复建议：hone explain H201。

try-catch 恢复：捕获可恢复错误（ZError 通道）；panic 类崩溃不进入捕获。 配合 --restart / --resume 实现无人值守运行。

try {
    resp = http_get("https://example.com/data");
} catch e {
    print(e.code + ": " + e.message);  // 字段: code/message/file/line/col/context
    resp = db.get("cached");        // 降级回退
}

throw "用户错误";   // 主动抛出 → error[H600]
throw e;             // 重抛已捕获的 error 值
机制说明
--restart[=N]脚本失败自动重拉（默认最多 3 次）；--backoff=a,b,c 重启间隔递增（默认 1,3,10 秒）；--restart-on=H200,H401 只对白名单错误码重启，确定性错误直接退出
--resume恢复上次 db 检查点；db.set 自动落盘 ~/.hone/state/，崩溃不丢检查点，脚本内容变更后检查点自动失效
错误对象字段e.code / e.message / e.file / e.context（str）；e.line / e.col（int）

注意：Hone 为块作用域，try/catch 块内赋值的变量在块外不可见，跨块共享的变量需在块前声明。示例见 examples/try_catch.hn、examples/restart_demo.hn、examples/resume_demo.hn。

#12. 设计原则

  • 不自举：Hone 不用于开发自己的编译器，保持设计与实现的灵活性
  • 不背兼容包袱：旧版本永久可用，新版本自由演化
  • 无前缀声明：变量不需要 let / var / const
  • 静态强类型：类型锁定，不隐式转换，报错精准
  • 单文件分发：下载 → 解压 → 运行，零配置；多版本共存互不干扰

#13. 图形界面库（hone_lib/gui.hn）

纯 Hone 编写的跨平台 GUI：浏览器渲染 + 本地 HTTP 服务器双向交互（Windows / Linux / Termux 均有浏览器）。依赖 server.* 内置函数。

import "gui" from "./hone_lib/gui.hn";

// 界面事件处理：id 为控件 id，value 为用户输入值（约定函数名 on_event）
fn on_event(id : str, value) -> str {
    if (id == "btn_hi") {
        return json_stringify({"update": [["lbl_out", "你好，Hone GUI！"]]});
    }
    return "";
}

widgets = [
    gui_button("btn_hi", "打招呼"),
    gui_input("txt_name", "姓名", "输入名字"),
    gui_label("lbl_out", "(事件输出)"),
];
gui_run("Hone GUI 演示", widgets);  // 启动本地服务器并自动打开浏览器，Ctrl+C 退出

控件：gui_button gui_label gui_input gui_select gui_html；on_event 返回值按 JSON 协议解释：{"update": [[元素id, 新文本], ...]} 更新元素、{"alert": "消息"} 弹窗、其他文本显示在页面底部状态栏。

底层 server.* API：server.listen(port) 启动后台监听（0=自动分配，返回实际端口）、server.poll() 取出排队请求（返回 JSON 数组）、server.respond(id, body) 发送响应体（HTTP 200）。事件模型为后台线程收发 + 脚本主线程轮询响应，与解释器单线程模型兼容。示例：examples/gui_demo.hn、examples/server_demo.hn。

#14. 进程检测库（hone_lib/process.hn）

纯 Hone 编写的跨平台进程检测库（Windows / Linux / macOS）：枚举进程、按名称/PID 查找、结束进程。Hone 无内置进程 API，本库经 sys.run 调用系统命令实现（Windows 用 tasklist / taskkill，Unix 用 ps / kill -9）。查询函数返回进程对象 {pid, name, mem, cmdline}（mem 为 KB；cmdline 仅 Unix 有值）。

import "process" from "./hone_lib/process.hn";

if (proc_exists("hone.exe")) { print("hone 正在运行"); }

// 枚举 / 模糊查找（不区分大小写）
for p in proc_find("chrome") {
    print(p.pid, p.name, p.mem);
}

// 结束进程（taskkill /F /PID 或 kill -9）
proc_kill(1234);
n = proc_kill_by_name("notepad.exe");  // 返回成功数

函数：proc_os proc_list proc_find proc_exists proc_by_pid proc_count proc_pids proc_names proc_kill proc_kill_by_name。跨平台差异：Windows 进程名含 .exe、Unix 不含，用子串匹配（如 proc_find("chrome")）两边通用。完整函数表与测试脚本见 标准库 · process 进程模块。

#15. 进阶用法（多文件 / 调试 / 性能）

15.1 多文件项目组织

单文件即可运行，项目变大后建议拆分模块。三种复用方式：

// import：.hn 源码复用（最常用）
import "math" from "./hone_lib/math.hn";   // 本地：相对当前目录
import "mod" from "https://.../mod.hn";   // 远程：缓存到 ~/.hone/cache/
import "mod" from "https://.../mod.hn" as m; // 别名：前缀替换为 m

// load：C 动态库（typed 签名块见第 9 章）
load "libm.so.6" as m {
    fn cos(x: float) -> float;
}

模块函数以「模块名_」为前缀注册（如 math_clamp、coll_sum）， as 别名可整体替换前缀。函数名全局唯一、不支持嵌套遮蔽，命名加前缀避免冲突。 推荐目录：入口 main.hn + libs/ 自有模块 + data/ 数据； 用 hone get <script.hn> 预下载脚本中所有 import 的模块。

15.2 函数别名（alias）

给已有函数起新名字再调用，原名保持不变：

// 基础：alias 原名 as 新名;  之后用新名调用
fn greet(name) { return "你好 " + name; }
alias greet as hi;
hi("Hone");          // 你好 Hone

// 原名支持点号路径（模块 / 类 / 内置点号函数）
alias random.int as rint;
rint(1, 100);         // [1, 100] 随机整数

// 别名可叠加（别名再起别名）、可指向内置函数
alias greet as hello;
alias hello as hey;
alias print as p;
p("OK");

别名作用域为文件级（当前 .hn 文件全局可见），在 alias 语句之后即可用新名调用。 完整示例见 examples/alias_demo.hn。

15.3 调试复杂逻辑

工具用途
hone debug <script.hn> + breakpoint;运行到断点暂停，打印当前作用域全部变量快照，Enter 继续 / Ctrl+C 退出
debug_print(expr);仅 debug 模式输出，普通运行自动跳过，可留在源码中
tmp fn 名称() { }临时函数，编译时自动忽略，适合开发期草稿
hone explain H201查看任意错误码的含义与修复建议
hone poop <file.hn>输出 if 嵌套深度与圈复杂度，定位「屎山」热点
hone test [目录]递归扫描 *.test.hn，配合 assert(条件[, 消息]) 汇总 PASS/FAIL
hone run --restart=3 --backoff=1,3,10 --restart-on=H200,H401崩溃自动重启（仅对可重入错误）；--resume 从上次 db 检查点继续

调试思路：先用 hone explain 确认错误码含义 → 在疑似出错处加 breakpoint; 观察变量快照 → 用 try/catch 捕获运行时错误并打印 e.code / e.message / e.line → 用 assert 固化关键不变量防止回归。

15.4 性能优化

  • 避免循环内反复 append：列表是值类型，append 返回新列表（整体拷贝）， 循环里 l = append(l, x) 是 O(n²)。累积数据时优先用 dict，或先确定规模再一次性构造
  • 字符串拼接优先 f-string：f"..." 比 + 简洁；str 不可变，大量拼接每次都会生成新串
  • 减少深拷贝：clone / copy 是递归深拷贝，只在需要独立副本时使用
  • 热点计算交给 C：瓶颈函数用 load 调用 C 库（FFI），或用 hone build --dll 导出后由 C 调用
  • 并行化：go 函数名(参数); 启动独立线程（值传递、不共享变量）， 适合可拆分的独立任务；线程间通信走文件 / HTTP / db
  • 先用 hone poop 找热点：优先优化嵌套最深、圈复杂度最高的函数；优化前先用 hone test 固化行为
