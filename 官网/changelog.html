v0.7.122026-09-25

新增

  • with 上下文管理器：with expr as r { ... }，进入时调 __enter__()（返回值绑定 r，仅块内可见），退出时（含报错路径）必调 __exit__()，错误不被吞。与 try/catch 正交：块内 throw 先执行 __exit__ 再向外传播（完整示例：examples/with_type_demo.hn）
  • type 实例类：type 名称 [extends 父类] { 字段: 类型, ...; fn 方法(self, ...) { ... } };，带方法、继承与构造器的实例类
    • 所有方法（含 init/__enter__/__exit__）必须把 self 作为显式首参，调用 obj.method(...) 时自动填充实例
    • 构造 new Type(实参...)：实参绑定 init 的参数（去掉 self）；无 init 时按继承链字段顺序（父类在前）绑定
    • 字段引用语义：方法体内 self.f = x 的写入对调用方实例立即可见
    • readonly 字段两种写法等价：readonly f: int / f: readonly int；与 struct（纯数据 dict，位置构造）互补
  • byte / bytes 字节类型
    • byte：8 位无符号值，字面量 0b1010001 或 byte(int) 显式转换（越界报错）；与 int 严格隔离（无隐式转换），to_int(b) / char(b) 回转
    • bytes：字节序列，字面量 b"abc"；支持 len / 索引（取 byte）/ 切片 / + 拼接 / == / for-in 迭代
    • 内置函数 byte / to_bytes(s, enc?)（默认 utf-8、支持 latin-1；int 列表 → bytes）/ hex / unhex；谓词 is_byte / is_bytes；type_of 返回 byte / bytes
    • JSON 序列化对 byte/bytes/type 实例明确报错（提示先转 str/hex 或组 dict）
  • readonly 只读修饰：只读变量 readonly int x = 5;（与 x : readonly int = 5; 等价）、只读参数 fn f(readonly int y) { ... }、struct/type 只读字段（静态拦截 + 运行时兜底）
  • 切片：a[i:j]（list / bytes；任一端点可省略 a[i:] / a[:j]），与 a[i] 索引同位置可链式（str 暂不支持切片）

变更

  • 字段赋值 obj.f = v：+=/-=/*=//=/%= 复合赋值在 AST 层展开为 obj.f = obj.f op v（各后端统一只见普通字段赋值）
  • 解释器 Value 新增 Byte(u8) / Bytes(Vec<u8>) / TypeInst 变体；struct 字段表记录 readonly 标志
  • AOT（build --exe -c）/ VM（--vm）/ DLL（build --dll）：type 实例、with、字段赋值、字节字面量为解释器特性，按既有"不支持即报 H999"模式兜底（goto 在 AOT 的同一处理方式）
  • 新增示例 examples/byte_demo.hn、examples/with_type_demo.hn；文档与官网同步（语言参考 §3/§7.5/§7.11、示例页 4.9）
v0.7.112026-09-13

新增

  • 标签与 goto（H105）：名字: 定义标签，goto 名字; 跳转（手工搭循环、一次性跳出多层嵌套、跳过一段代码）。编译期安全校验，运行期绝不跳到未定义位置：
    • 标签必须与 goto 同函数、同名唯一；只能跳到从跳转点向外层可见的标签，无法跳进 if / 循环等内层语句块
    • 禁止向前跳过变量绑定（x = ... / int x = ... / 解构赋值），避免读到未初始化变量
    • 标签写法 loop_top: 与类型注解 x : int = 10; 无歧义：冒号后同行还有内容即按类型注解解析
    • 解释器与字节码 VM 均完整支持；AOT 原生编译（build --exe -c）暂不支持 goto，报 error[H999]（尚未实现）并提示改用 hone run / hone run --vm
    • 示例 examples/goto_demo.hn；回归 regress3.py / regress_ir.py 均纳入比对
  • 宏 macro（H106）：表达式宏 macro NAME(形参) => 表达式; 与语句宏 macro NAME(形参) { 语句... }，调用写法与函数一致（NAME(...)）
    • 解析后、类型检查前由新增的预处理阶段（src/preproc.rs）做纯 AST 替换，因此解释器 / 字节码 VM / AOT 三个后端行为完全一致，运行期不存在宏
    • 安全约定：宏只能在顶层定义、先定义后使用（若调用的名字对应更靠后的宏定义，直接报 H106 并指出定义行号，提示把定义上移）；宏体在定义点展开（只能引用更早的宏 ⇒ 引用无环，不可能无限展开，无需深度上限）；宏名不得与函数 / async fn / 结构体 / 类 / 枚举或其他宏重名；实参个数必须匹配
    • 表达式宏体内禁用 ++ / -- 与 lambda，形参不得用作被调用函数名；语句宏展开为独立作用域块（变量不外泄），体内禁用 return / goto / 标签 / 嵌套 macro，break / continue 仅限宏体自身的循环
    • 形参可作简单赋值目标（INC(i) → i = i + 1;），实参须为裸变量名
    • 示例 examples/macro_demo.hn
  • 新增错误码 H105（标签/跳转）、H106（宏），hone explain H105/H106 提供修复建议

变更

  • src/preproc.rs（新增）：所有解析入口（Parser::parse）统一挂载「宏展开 + 跳转校验」，保证 hone run / --vm / --disasm / AOT / LSP / REPL 走同一份语义
  • 文档与官网同步更新（语言手册、更新日志、进阶用法新增 goto / 宏章节与 H105 / H106 错误码说明）
  • 新增 src/cgen_util.rs：两个 C 后端（aot.rs 与 codegen.rs）共用的机械转义层，并修复 --dll 的真实缺陷：原先控制字符用十六进制 \x 转义，而 C 的 \x 转义是贪婪的（"\x01a" 会被解析成单字节 \x1a），导致含控制字符的字符串被静默截短；现统一为三位八进制并加 4 个单元测试锁死该回归。两者值模型不同（--dll 用 C 原生类型对接 C ABI、AOT 统一装箱），代码生成主体不共用
  • AOT 后端评估完成：保留并投入，不移除。实测推翻「AOT 性价比不高」的初始假设，AOT 相对解释器有接近一个数量级的稳定加速：fib(26) 9.5x（267 ms vs 2530 ms）、循环 200 万次 12.1x（514 ms vs 6203 ms）；产物体积约 58.6 KB。同时如实记录性能短板：生成的 C 对每次整数运算都做装箱与深拷贝，等价 rustc -O 跑 2000 万次循环约 274 ms、AOT 版约 2962 ms（慢约 10 倍），调高优化级别无效——这是值语义 + 统一装箱的必然代价，故不宜宣称「接近 C 的性能」
  • 修正文档中与实现不符的描述：hone build --dll 原先写作「内置 TinyCC（约 200 KB），无需用户安装外部工具链」，实测 Cargo.toml 无任何 C 编译器依赖，find_cc() 走 CC 环境变量 > gcc > clang > cc，与 AOT 一样依赖系统 C 编译器
  • 回归基线：示例逻辑比对（regress3）、错误码（regress_err）、字节码反汇编（regress_ir）三套全部达标，真实逻辑差异为 0；少量不一致均为随机数 / 端口 / 时间等非逻辑差异
v0.7.102026-08-30

新增

  • char 字符类型：单个 Unicode 字符，全链路支持（词法/AST/解析/静态检查/解释器）
    • 字面量：单引号 'a' / '\n' / '\'' / '中' （转义同字符串 + \'；必须恰好一个字符，空/多字符报 H005）； 类型注解 char c = 'x';（C 风格与 c : char; 风格均支持）， x : char; 无初值时默认 '\0'

    • 内置函数：ord(c)（字符 → 码点）、char(i)（码点 → 字符，越界/代理区报错）、 char_at(s, i)（按 Unicode 字符取串中第 i 个字符 → char，区别于 s[i] 返回单字符 str）、 char_upper(c) / char_lower(c)（大小写）、 char_is_digit(c) / char_is_alpha(c) / char_is_space(c)（字符分类）
    • 集成：to_str(c) → 单字符字符串；type_of('a') → "char"； JSON 序列化为字符串；match 模式支持字符字面量；fmt 兼容；--dll 导出按码点 int 映射； AOT 原生编译暂不支持；示例 examples/char_demo.hn
