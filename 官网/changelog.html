#更新日志

各版本的新增 / 变更 / 修复 / 文档汇总。最新版本见顶部 v0.8.0 区块。

Unreleased 开发中

移除

  • 移除 NAT（build --exe --native / natgen）与 DLL（build --dll / @export）后端：维护面积收敛到 interp + VM 双引擎；旧命令现报 H005，help 指向本条。v0.8.0 的 NAT 工作作为历史保留（见下方 v0.8.0 区块）。hone load 运行期动态库加载（H301/H302）不受影响。本开发周期内曾落地的 NAT 工具链调整（纯 .o 生成器 / runtime-a 预编译资产 / natgen --obj 语义统一 / 链接路径口径）随整体移除，不再单列；natgen.rs、runtime/（honeruntime crate）与 cranelift / target-lexicon 依赖删除。回归脚本相应改为双引擎（regress4.py / regress_err.py / probe_align.py），tests/tools/audit_err.py 删除。

新增

  • VM 补齐解释器特性（8 项，probe_align 271 例逐字节对齐）：VM（--vm）现完整支持原先仅解释器可用的特性——切片 a[i:j]（负索引归一/越界钳制/bytes 切片）、byte/bytes 字面量（0b… / byte() / b"…"）、字段赋值 obj.field = x（dict/struct/type 实例、readonly 拦截、__struct__ 隐藏键过滤、嵌套链值语义）、默认参数（省略尾部实参按默认表达式求值，可引用其前形参）、with 上下文管理器（块内 break/continue/return 穿透时 __exit__ 仍必调）、type 实例类（构造 / init / self 写字段 / extends 继承 / 方法覆盖 / 引用语义）、debug 模式（breakpoint 变量快照 + Enter 等待）。新指令 Slice/FieldSet/TypeNew/WithEnter/WithExit/Breakpoint/CallMethod 已同步文本 IR 往返。probe_align 新增 slice/byte/bytes/field/with/type/import 七组（含本地 http server fixture，避免 CI 联网）。
  • VM 下 import 远程模块走构建期展开 + 修复检查范围分歧：--vm 编译期经 resolve_imports 展开顶层 import（本地路径相对 CWD；远程 http(s) 下载并缓存到 ~/.hone/cache/）。修复 checker 与 resolve_imports 的顺序——checker 现在展开前运行，只静态检查主模块源码，与解释器 / hone check / hone prof 一致；否则展开进来的模块函数体（尤其未被调用者）会在 strict 阶段被误报 H003。
  • FFI 回调 + 变参全链路支持（仅解释器实测通过；VM 不支持 load，报 H999）：删 ffi_dispatch!/ ffi_variadic! 穷举宏（8190 类型实例化内存峰值），切换为 libffi 静态构建（ffi_prep_cif/ ffi_prep_cif_var/ffi_call + ffi_closure 回调）。支持 int/int32/float/float32/bool/str/ptr/void 全标量参数与返回，回调 0-8 参、变参无固定上限、float 固定参数的变参函数已支持。
  • int32/float32 新类型全链路：lexer/parser/header/checker/interp/VM/签名块/头文件绑定 全覆盖；C int32_t/uint32_t 映射 int32，C float 映射 float32。
  • install.bat 纯 ASCII 安装脚本：原生 curl.exe+tar.exe，镜像回退/sha256 校验/断点续传/PATH 去重/--uninstall 卸载/幂等，功能对齐 install.sh；Windows 安装 = 双击 install.bat。
  • CI 恢复多核极速：删 -j 1 与 swap/页面文件，保留 actions/cache@v4。

变更（破坏性变更）

  • 废弃 cow 声明（BREAKING）：cow 关键字语法整体移除——引用模型改造后，全部容器（list/dict/str/bytes）默认走 O(1) 句柄共享 + 写点自动隔离（ensure_unique 门控），别名不可见、可观察行为与旧值语义逐字节一致，cow 显式声明失去存在意义。代码中遇 cow 报 H005 语法错误（help 指引改用普通赋值，语义不变）；cow 形参同理。内部实现同步删除：Value::Cow 变体、COW 三件套、Env.cow_vars、VM/DLL 的 cow H999 边界；fmt 关键字表移除 cow；tests/smoke/cow_read.hn 随语法移除（断言已由普通值路径回归覆盖）。
  • 移除 install.ps1 / build_toolchain.py / targets/ 工具链分发 / HONE_NAT_LINK 环境变量； full 包仅含 hone 本体（无 targets/）。
  • 头文件绑定不支持列表缩减：数组参数/结构体按值/long double 仍 unsupported； 变参与回调现已支持（hone bind 输出列为支持）。

变更（byte/bytes 内置函数返回值修正，含破坏性变更）

  • zlib.compress / zlib.gzip → bytes（原 base64 str）：压缩结果是二进制，直接返回字节序列；需要字符串形态用 crypto.base64_encode 显式编码；参数额外接受 bytes（str 按 UTF-8 字节）
  • zlib.decompress / zlib.gunzip → bytes（原 str）：解压不再强制 UTF-8（原 read_to_string 会拒绝非 UTF-8 内容）；输入接受 bytes，str 输入按 base64 兼容旧版形态
  • ws.request → list（原拼接 str）：返回消息列表，每条消息一个元素——文本帧为 str、二进制帧（opcode 0x2）为 bytes（原实现二进制帧被静默丢弃）
  • 新增 http_get_bytes(url) / http_post_bytes(url, body) → bytes：二进制响应体（图片 / PDF / zip 等）不经 UTF-8 边界；http.request 新增 binary: true 选项（响应体按原始字节返回），str 行为不变
  • 新增 archive.tgz_read_bytes(path, entry) → bytes：与 zip_read 对称（tgz_read 维持 str 仅文本）
  • read_bytes(path) → bytes（原 list[int]）：返回真正的字节序列（索引得 byte 值、for-in 迭代字节、+ 拼接、len 为字节数）；checker 静态返回类型同步
  • crypto.base64_decode(str) → bytes（原 str）：二进制安全（原实现经 from_utf8_lossy 会破坏非 UTF-8 内容，属 bug 修复）
  • archive.zip_read(path, entry) → bytes（原 str）：二进制安全（原实现经 read_to_string 会拒绝非 UTF-8 条目，属 bug 修复）；archive.tgz_read 维持 str（仅文本）
  • ptr.read_byte(p, offset) → byte 值（原 int 0-255）：与 int 严格隔离，回转用 to_int
  • 参数侧补充（非破坏）：crypto.base64_encode 额外接受 bytes；write_bytes 额外接受 bytes 值；ptr.write_byte 额外接受 byte 值（原 list/int 形态均可用）
  • VM 行为对齐：for a, b in <list/bytes> 双变量迭代原在 VM 静默放行（第二变量取陈旧值）， 现与解释器一致报错 ` for k, v in requires a dict, got a list/bytes `
  • checker 新增双形态参数检查（expect_str_or_bytes / expect_int_or_byte）；LSP 补全描述同步

修复

  • 原生编译后端的能力边界报错口径统一为 H999（M2 G2.7）：此前未实现的指令报 H990 internal 「指令未实现（M0 子集外，T3/T5+ 落地）」（文案早已过时），现报 H999 原生编译后端暂不支持 \await\（见 M2 G2.6 async-await） + help「用解释器运行同一脚本」， 与 VM / DLL 对同类特性（with、字段赋值）的 H999 口径一致
  • 新增单测强制「每个字节码指令都有显式决策」（G2.7）：Instr 的每个变体都必须有 lowering 臂 / 块级处理，或在 NOT_IMPLEMENTED 表里带理由登记——新增指令若漏决策，测试直接失败并列出漏项， 不再静默落到兜底 H990
  • 原生编译后端支持 alias / goto（M2 G2.5）：alias 原名 as 新名 在原生后端可用—— runtime 增加别名表（call_global 入口解析，可叠加），natgen Call lowering 编译期解析别名 以决定走 rt_callv（局部变量目标）还是 rt_call（全局目标）；goto（Label+Jmp）基线已覆盖， 本轮补用例固化
  • alias len as mylen 这类「别名指向内置」的形态在原生后端原先报 H002， 现可用；连带修掉一处极隐蔽的 wrapper 缺陷——别名的原名若从未作为调用名出现 （len 只出现在 alias 声明里）就会拿到错误的 strtab 索引，症状是报错指向一个无关的函数名
  • 解释器「别名指向变量」形态对齐 VM：VM 的 do_call 把 resolve_alias 放在局部变量查找 之前，解释器却只在 call_fn 末尾查函数表 —— alias gvar as g2; g2(1) 解释器报 H002、 VM 正常。改为一律「先解析别名（可叠加）再走完整分派」，「别名即透明改名」三引擎成立
  • 原生编译后端支持运算符重载（M2 G2.4）：__add / __sub / __mul / __div / __mod / __eq / __ne / __lt / __le / __gt / __ge / __neg / __not / __len / __index 回退链（触发条件逐条镜像解释器：算术限「非数字/str 组合 + H001」，比较限「非数字对」， 除零/溢出等内建错误不回退）；实现落在 runtime，字节码与 lowering 无需改动
  • 参数个数校验三引擎对齐：fn f(a) 被以 2 个实参调用（经运算符重载路径可达）时， VM 与原生后端原报中文硬编码消息且无定位无 help，现统一为解释器文案 （expects at most N arguments, got M / `missing argument c of f `）+ 定位 + help
  • && / || 改为真正的短路求值（此前 VM 在分支前无条件求值右侧）：false && f() / true || f() 原先仍调用 f（副作用可见），且 true || (1 / 0 == 0) 原先触发除零——现与解释器一致： 左侧恰为 false（&&）/ true（||）才短路，否则求值右侧
  • 条件站点严格 bool 校验（解释器运行期兜底，VM 原先按 truthy 静默放行）：if / while / do-while / for / 三元 / 推导式 if 过滤六处，非 bool 条件（enum、struct、字符串等动态值） 改报 H001 且消息按站点区分；do { } while (enum) 原先死循环
  • 逻辑操作数严格 bool：&& / || 右侧非 bool 报 H001「logical operators require bool operands」（原先当 truthy 处理并直接返回该值）
  • match 无匹配分支的错误码对齐：原 VM 抛字面串 → H600「match failed: 无匹配分支 (H005)」， 与解释器的 H005「no match arm matched the value」+ help 不一致——改走 Instr::Raise， 三引擎逐字节一致（runtime 侧 rt_raise 错误码白名单与文本 IR 装配同步补 H005）
  • match 绑定变量作用域：绑定原先插进所在作用域且从不弹出，会顶掉外层同名变量 （绑定后外层变量在 VM 侧被改写，解释器分支结束即出作用域）；改为「临时区声明 + 分支作用域」， 外层同名变量不受影响
  • lambda 捕获取内层同名变量：捕获表原先按「外→内」遍历且首见即取，遮蔽场景下捕获到被遮蔽的 外层值（match 绑定遮蔽外层名时，闭包拿到外层值而非绑定值）——改为与 lookup 同序（内层优先）
  • 解构非容器值的错误文案：VM 原用值显示（got 5），解释器用类型名（got int）——VM 改用 type_name()，三引擎一致（既有用例被 print 参数数静态错误掩盖，本轮补运行期用例）
  • 解释器整数取负溢出改抛 H010：-x 遇 i64::MIN 原先直接 panic（attempt to negate with overflow），与 VM / nat 后端行为不一致——改为 checked_neg 并报H010（带 help），三引擎统一

  • VM 解构错误文案对齐解释器：区分列表 / 字典解构形态不符（各有专属 help）、列表元素数不足时 报实际变量数并补help
  • CI 的 nat 三引擎回归（Linux job）16 例全灭：回归脚本在 Linux 上强制 --target x86_64-unknown-linux-musl，而 runner 未装该目标的 Rust std，rustc 报 E0463: can't find crate for 'std'。三处一起修：

新增（新语法）

  • 三引号原始字符串："""...""" 多行字符串，不做转义处理、原样保留换行与缩进
