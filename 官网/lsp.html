#LSP 配置指南

Hone 内置语言服务器（hone lsp，LSP over stdio，零依赖零配置），任何支持 LSP 的编辑器接入后即可获得补全、实时诊断、hover、跳转定义/类型定义、引用查找、重命名、格式化、折叠区域、签名帮助、文档大纲与语义高亮。本页给出主流编辑器的接入配置。

#1. 快速开始

确认 hone 已安装并在 PATH 中（见 安装教程），然后验证 LSP 可启动：

hone --version    // 确认版本 ≥ v0.7.6（LSP 首发版本）
hone lsp          // 启动语言服务器：阻塞等待 stdio 上的 JSON-RPC 消息（Ctrl+C 退出）

看到进程挂住不退出即为正常——语言服务器通过 stdin/stdout 交换 JSON-RPC 消息，由编辑器客户端负责启动和管理它的生命周期。你不需要手动运行它，配置好编辑器后打开 .hn 文件即自动拉起。

协议实现要点：增量文档同步（didChange range 替换）、诊断经 textDocument/publishDiagnostics 推送（语法 + 类型错误，含错误码 Hxxx，可用 hone explain <code> 查看解释）、未知方法按规范返回 -32601 Method not found。

#2. 能力一览

服务器在 initialize 响应中声明以下能力（服务名 hone-lsp）：

能力说明
textDocument/completion补全，触发字符 .（点号内置族 time.now 等自动补全）
textDocument/hover悬停信息
textDocument/definition / typeDefinition跳转定义 / 类型定义
textDocument/references查找全部引用
textDocument/rename重命名符号
textDocument/formatting整文档格式化（复用 hone fmt 引擎）
textDocument/foldingRange折叠区域（多行块 / 文档注释）
textDocument/signatureHelp签名帮助，触发字符 ( ,
textDocument/documentSymbol文档大纲（fn / struct / enum / type，AST 驱动）
workspace/symbol工作区符号搜索
textDocument/semanticTokens/full语义高亮（keyword / type / function / variable / string / number / comment / namespace / class / struct）
publishDiagnostics诊断推送（打开 / 修改时自动推送语法与类型错误）

#3. VS Code

Hone 目前未发布官方 VS Code 扩展，通过支持「自定义 stdio 语言服务器」的通用 LSP 客户端扩展接入（扩展市场搜索 "LSP client" / "custom language server"，任选一个维护活跃的，如 LSP Client 类扩展）。通用配置思路一致——注册语言 hone，服务器命令 hone lsp，按 .hn 文件激活：

{
  "lsp-client.languages": {
    "hone": {
      "command": "hone",
      "args": ["lsp"],
      "extensions": [".hn"]
    }
  }
}

不同扩展的设置键名略有差异，但三个要素不变：命令 hone、参数 lsp、扩展名 .hn。若扩展支持语义高亮请求（semanticTokens），打开 .hn 文件后即自动生效；不支持时编辑器以 TextMate 着色兜底。

配置完成后重启 VS Code，打开任意 .hn 文件，右下角状态栏出现语言服务器标识、保存时有诊断推送即接入成功。

#4. Neovim（0.8+，内置 LSP）

Neovim 无需插件，直接用内置 vim.lsp 注册客户端配置。在 ~/.config/nvim/lua/lsp/hone.lua（或 init.lua）加入：

-- ~/.config/nvim/lua/lsp/hone.lua（nvim 0.11+ 也可放 lsp/hone.lua 用 vim.lsp.enable）
local config = {
  name = "hone-lsp",
  cmd = { "hone", "lsp" },
  filetypes = { "hone" },
  root_markers = { "hone.json", ".git" },
  settings = {},
}

if not configs.hone_lsp then
  configs.hone_lsp = {
    default_config = {
      cmd = config.cmd,
      filetypes = config.filetypes,
      root_dir = function(fname)
        return vim.fs.root(fname, { "hone.json", ".git" }) or vim.fs.dirname(fname)
      end,
    },
  }
end

vim.api.nvim_create_autocmd("FileType", {
  pattern = "hone",
  callback = function(args)
    vim.lsp.start(config)
  end,
})

并把文件类型注册进 init.lua：

vim.filetype.add({ extension = { hn = "hone" } })

使用 nvim-lspconfig 的用户可直接在 ~/.config/nvim/lua/lspconfig/hone.lua 写一个同名自定义 server（内容即上面的 cmd / filetypes / root_dir），效果相同。打开 .hn 文件后 :LspInfo 显示 hone-lsp 已附加即成功；语义高亮与文档大纲开箱即用。

#5. Helix

在 ~/.config/helix/languages.toml 加入（Windows 路径为 %AppData%\helix\languages.toml）：

[[language]]
name = "hone"
scope = "source.hn"
file-types = ["hn"]
language-servers = ["hone-lsp"]
roots = ["hone.json", ".git"]

[language-server.hone-lsp]
command = "hone"
args = ["lsp"]

保存后重启 Helix，打开 .hn 文件，:lsp-stop / 状态栏语言图标确认服务器已连接。诊断自动显示在状态区；space + s 可用文档大纲（documentSymbol）跳转函数 / struct。

#6. Emacs

推荐 eglot（Emacs 29+ 内置）：

;; init.el —— 定义 hone 模式并挂接 eglot
(add-to-list 'auto-mode-alist '("\\.hn\\'" . hone-mode))
(define-derived-mode hone-mode prog-mode "Hone")
(add-to-list 'eglot-server-programs
             '(hone-mode . ("hone" "lsp")))
(add-hook 'hone-mode-hook #'eglot-ensure)

使用 lsp-mode 的用户等价配置：

(lsp-register-client
 (make-lsp-client :new-connection (lsp-stdio-connection (lambda () (list "hone" "lsp")))
                  :major-modes '(hone-mode)
                  :server-id 'hone-lsp))

打开 .hn 文件后 M-x eglot（或自动）连接，M-x eglot-events-buffer 可排查协议交互。

#7. Kakoune

通过 kak-lsp 接入，在 ~/.config/kak-lsp/kak-lsp.toml 加入：

[language.hone]
filetypes = ["hone"]
roots = ["hone.json", ".git"]
command = "hone"
args = ["lsp"]

并在 kakrc 中注册语言与 hook（set-option buffer filetype hone、按扩展名触发 lsp-enable）。

#8. 故障排查

现象排查
服务器无法启动终端里直接运行 hone lsp：若报「命令未找到」是 PATH 问题；配置里可写 hone 的绝对路径（which hone / where hone 查询）
无补全 / 无诊断确认编辑器把文件识别为 hone 语言（扩展名 .hn；Neovim 检查 :set ft?）；确认客户端启动的命令是 hone lsp（缺 lsp 参数会当成脚本运行而立即退出）
协议报错 / 功能缺失查看编辑器的 LSP 日志（VS Code 输出面板；Neovim :LspLog；Emacs eglot-events-buffer）。 hone-lsp 对未知方法返回 -32601 属正常——客户端请求的能力需在上方能力表内
诊断更新不及时诊断在打开 / 修改时推送（增量同步）；确认客户端未禁用 publishDiagnostics
多根工作区 hone-lsp 为单文件 / 项目目录级服务，root 取 hone.json 或 .git 所在目录，未找到则退回文件所在目录

端到端协议行为有 tests/lsp_smoke.py 冒烟测试背书（stdio 启动服务器，验证全部能力与协议错误码）。遇到问题欢迎到 GitHub Issues 反馈。
